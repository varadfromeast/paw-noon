# Code review, 20 Oct 2026

Scope: M1 difficulty (`43f4c67`), M3 backend (`1e53dab`), and the recent runtime work (heart monitor, vignette, swipe hint, input timing).
Branch `agent/review`. The fixes are in the commits listed in §1. §2 lists what is deferred, with file:line, severity and a proposed fix. §3 is the improvement list. Anti-cheat proposals for ghost duels are in `Docs/M5_PLAUSIBILITY.md`.

Severity: **High** means wrong results or data loss in normal use. **Medium** means a realistic failure or abuse path. **Low** means hygiene, or a problem only under unusual conditions.

Checked and found OK: `CopyFrom` happens only on the title screen or at the next `StartDuel`; the authority, clients and bot read the config live, with no cached copies. The heart monitor, vignette thump and hold vignette depend only on time since the hold began, never on the cue. The ECG is hidden in the DRAW frame, so it adds no work to the frame whose start time is the cue estimate. The `NetRandom` port, banker's rounding and the damage/grade ports match C# (TS suite incl. parity vectors: 21/21). Every Edge Function authenticates via `requireUser`. `SECURITY DEFINER` helpers pin `search_path` and are `service_role`-only. There's no string-built SQL anywhere (all PostgREST builders or parameterised plpgsql).

## 3. Improvements worth doing

1. **CI**: one GitHub Action that runs `node Tools/Parity/run_node_tests.ts` (or `deno test`), `supabase/scripts/sync_duel_config.sh --check` and `python3 Tools/Parity/reference_vectors.py --check` on every PR, plus Unity EditMode tests through game-ci on a nightly schedule. The parity tests exist but nothing enforces them yet.
2. **Prod guard rails**: fail the deploy script if `PN_ALLOW_INJECTED` or `PN_RANKED_ALLOW_GUESTS` is set in the production project's secrets.
3. **Latency calibration screen** (feel + fairness): a "tap on the flash" pass of 10 flashes that sets `presentLatencyExtraMs` per device. That removes most of the constant bias described in TIMING §6 and makes cross-device ghost duels fairer.
4. **Atomic submit** (D1): `pn_complete_match` in SQL.
5. **IL2CPP stripping**: with `link.xml` in place, try Managed Stripping Level = Medium on Android and iOS (smaller binary), and add a smoke build to CI.
6. **Warnings as errors** for the PawNoon asmdefs (`csc.rsp` with `-warnaserror`) now that the known warnings are gone, so new dead fields or obsolete APIs fail fast.
7. **`IOpponent` first** (M4 prep): pull Blackpaw's acting and banter behind `IOpponent` before `GhostOpponent` lands (D2). It's also the first cut for shrinking `DuelDirector` (about 1270 lines) into round flow, acting presenter and result presenter.
8. **First-draw tutorial round**: the first round of the first match deals no damage and waits for a swipe after DRAW, with the hint visible. "A plain click doesn't fire" is the most likely first-session failure.
9. **Ghost fairness card**: on the opponent card, show the ghost's device refresh rate and whether its input was frame-quantized. That's cheap (already in the recording) and explains surprising results.
10. **Per-difficulty BEST** (D8) and an EASY badge on the title BEST line, so Easy runs can't masquerade as Hard records.
