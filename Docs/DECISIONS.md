# Current direction

User-confirmed: portrait iOS; reaction-only quick draw; animal outlaws, cats only for now. The supplied image defines atmosphere rather than a timing-meter mechanic.

Implementation choices: Dust & Claws working title, grey tabby player versus orange tabby Blackpaw (renamed **Pawtruth** in Spec v2), offline bot MVP, health-based repeated exchanges, new art, built in the empty PawNoonPixel shell. The original PawNoon project is reference-only.

Later product decisions: final name, online PvP scope, additional outlaw characters and progression, music direction. These do not block this playable slice.

# M1 notes: Difficulty (SPEC_V2 §1)

- **Rules files.** Hard is `Resources/Data/duel_config.json` unchanged. Easy is `Resources/Data/duel_config.easy.json`, which holds only the 15 keys in the §1 table. `DuelConfig.Load(hardJson, overlayJson)` merges the overlay with `PnJson.Merge`: overlay keys win, nested objects are merged one level deep, and arrays are replaced whole. `DuelConfig.FromJson` still works as before. `DuelConfig.Difficulty` is `"hard"` or `"easy"` and is set by `Load`, never read from JSON.
- **Switching rules without rebuilding the core.** The authority, clients, bot and director all hold the same `DuelConfig` reference and read it live. A difficulty change copies the new values into that object (`DuelConfig.CopyFrom`). On the title screen the copy happens at once. Otherwise it happens at the next `StartDuel` / `ShowTitle`, so a match in progress keeps its rules. No change to Core timing, `SwipeDraw` or `LocalAuthority`.
- **Persistence.** PlayerPrefs key `pn_difficulty` (`"easy"`/`"hard"`). On first launch there is no key, so the title shows a one-time **PICK YOUR DUEL** card (panel_wood with btn_large_alt EASY and btn_large HARD). PLAY, the gear and the toggle wait until the player picks. After that, an EASY | HARD segmented toggle sits under PLAY, using the same seg_on/seg_off sprites as the settings music-style row, and BEST moves under the toggle.
- **Tags.** These are text only, with no new art. The HUD puts EASY/HARD just right of the round sign on the same row, because the row below the sign is where the result card sits. The round result card puts it after the note line ("TAP TO CONTINUE  EASY").
- **Bridge.** `ReviewDirector.SetDifficulty easy|hard|reset` and `ReviewDirector.Show difficulty`. `Status` now reports `difficulty=`, shown as `hard->easy` while a change is waiting for the next match.
- **Tests.** `DifficultyTests` checks the following. The overlay file keys equal the whitelist. Merged Easy differs from Hard in exactly those fields. Easy 300 ms deals Hard ~220 ms damage (35 vs 33.6 HP, same PERFECT band). Easy is never harsher than Hard. anticipationMs, tieWindowMs and the countdown are unchanged. The merge semantics and `CopyFrom` are covered too.

# Polish notes: Pawtruth rename, banter + voice, haptic language, match intro (SPEC_V2 §8.2, §8.6, §8.7)

- **Rename.** The bot persona is **Pawtruth** everywhere the player sees it: `botName` in `duel_config.json`, the HUD name plate, the result card, the "PAWTRUTH JUMPED THE GUN!" message, docs and comments. Asset folders keep their names (`Art/Characters/Bandit`, `bandit_*` sprites). The C# field `DuelConfig.blackpawLines` and its JSON key stay as the legacy fallback (below). The server's recording `character` enum still says `"blackpaw"` (M3 code, untouched); `CharacterRoster.Normalize` maps `"blackpaw"` to `"pawtruth"`, so either id works on the client.
- **characters.json (§8.2).** `Resources/Data/characters.json` holds each cat's `name`, `meow` (SFX key) and `lines` (same seven contexts as before). Fallback is per field and per context: Pawtruth takes a missing context from `duel_config.json` `blackpawLines` (kept for **one release**, marked by `_blackpawLinesNote`), then from the built-ins; Whiskers takes it from `BanterLines.WhiskersDefaults()`. A missing or broken file never breaks the game. The lines are what a cat says **as the opponent**. The director takes the opponent's profile through `DuelDirector.SetOpponent`, and `PawGame` sets Pawtruth for now (`CharacterRoster.OpponentOf("whiskers")`). M2 only has to pass the other id.
- **Whiskers' voice.** There are 20 lines: plucky, dry, short, never above 30 characters, and none reused from Pawtruth. He calls the black cat "shadow" / "big cat".
- **Meow signature.** `Tools/AudioGen/gen_voice.py` writes `sfx_meow_whiskers.wav` and `sfx_meow_pawtruth.wav` (48 kHz mono, 0.36 s, peak -1.0 dBFS, DC < 2e-5). Each is three polyBLEP pulse notes whose pitch and duty step at 60 Hz (an 8-bit driver feel), and a continuous vowel filter (stepping the filter clicked, so it was removed). Whiskers is B5 E6 C#6, 25 % duty and bright. Pawtruth is E4 A4 D4, square, a sub-octave and a 31 Hz pitched growl (AM), with no noise sources, so there is no hiss. `PawAudio.PlayMeow` plays the opponent's meow at volume 0.6, pitch ±4 %, whenever his bubble pops (the bubble's own soft tap stays).
- **Haptic language (§8.6).** `Core/HapticPattern.cs` defines the patterns `{pulse, gapMs, pulse, ...}`: LIGHTNING = heavy ×3, 65 ms apart; PERFECT = medium + heavy, 85 ms apart; GREAT = medium; GOOD / SLOW / SLOWPOKE = light; TOO EARLY = notify error; NO SHOT = notify warning. The patterns play when the result-card stamp lands (they replace the old single medium tap). `HapticSequencer` is pure and allocation-free, and gaps accumulate, so the rhythm does not drift with frame rate. `PawHaptics.Pattern` starts a pattern, and `DuelDirector.Tick` advances it every frame through `PawHaptics.Tick` (no coroutine). The Haptics toggle off cancels a running pattern. Reduced Motion plays only the first pulse. 65 ms is the shortest gap that stays three distinct taps on a Taptic Engine.
- **Match intro (§8.7).** Only on the first match of a session, and only with `introEnabled` (default true): the opponent slides in from past the right edge (0–0.85 s), and the hero comes from past the bottom-left (0.15–1.05 s, also rising 40 px). Both use idle frames, whole-pixel offsets and a cubic ease quantised to 12 steps/s. The name plates then slam down onto the HUD (-7, -2, +1, 0 px in 40 ms steps) with `sfx_stamp`, a light tap and a 1 px shake, at 1.10 s (YOU) and 1.24 s (opponent). The normal standoff (GET READY, swipe tutorial, his opening line) starts at 1.6 s. A tap after 0.15 s skips to the end. Reduced Motion: no slides; the plates appear (with the stamp) at 0.2 / 0.4 s and the intro ends at 0.9 s. The intro only holds the standoff timer, so the countdown and every timestamp are untouched. `ReviewDirector.StartDuel` and auto-tap runs never show it unless `ReviewDirector.SetIntro on`.
- **Why the intro is a plain class ticked by the director**, and not a MonoBehaviour: it has to hold the standoff (`if (intro.Tick(dt)) break;`), and that is a one-line hook in `DuelDirector`. Everything else lives in `MatchIntro.cs` plus two small `DuelHud` methods (`SetName`, `SetNamePlate`).
- **Bridge.** `call PawNoon.Runtime.ReviewDirector.SetIntro on|off|auto|reset` (reset = auto + forget "shown this session"). `Status` now reports `intro=auto(shown)` (and `(playing)`) and `opponent=pawtruth`.

# M8 notes: replay strip and LAST LIGHT (SPEC_V2 §8.1, §8.4)

- **Replay strip (§8.1), presentation only.** `Runtime/ReplayStrip.cs`. It's a 200×24 point-filtered texture (2 px taller than the suggested 22, so the name row, ticks, ruler and gap row each get their own pixel rows), drawn like `EcgMonitor` into a preallocated `Color32[]` and redrawn only when the stepped build-in changes. It sits 2 px under the round card. The ruler runs from 0 to `max(600, slower timed reaction + 50)` ms with a tick every 100 ms. DRAW (0) is a signal-yellow post with a star. You are a cream tick, the opponent is a red tick, and the ruler between two clean shots turns yellow, with the gap (`opp − you`, so `+` means you were faster, as on the card) rounded to 0.1 ms in the small font. Anticipation fouls get a crossed tick at their reaction. TOO EARLY, NO SHOT and "stopped" get a crossed tick at the right edge, and when both are there "you" sits 8 px left of it. Labels centre on their tick and push apart around the midpoint when they would touch. Build-in: the ruler sweeps in 10 px steps over 60 % of `replayStripSeconds` (0.35 s), then the ticks drop −4/−2/0 px, then the labels appear. There are no alpha fades. With Reduced Motion it all appears at once. Data comes from the authority's `RoundRecord` (`ReplayMarks.FromRound`). It never touches Core, reaction measurement or ShotReports. If the strip would reach the live timer row (tall phones, where the card sits lower), the director hides the timer for the result, because the card already shows the same time. All the maths is in `ReplayStripMath` (engine-free) and is tested in a new assembly `PawNoon.Tests.Runtime` (`Code/Tests/EditModeRuntime`), because the existing test assembly only references Core.
- **LAST LIGHT rule (§8.4).** `Core/SuddenDeath.cs`: it triggers when `suddenDeathEnabled` is on and **both** cats are alive and at or below `suddenDeathHp` (20, inclusive) as a standoff starts. The round's damage is then multiplied by `suddenDeathDamageMultiplier` (2). The authority does not decide on its own. The match driver calls `LocalAuthority.SetDamageMultiplier(SuddenDeath.MultiplierFor(cfg, match))` before every standoff (`DuelDirector.BeginStandoff`). The value is latched into `RoundRecord.damageMultiplier` at `StartCountdown`, so a round in flight can never change, and `DamageFor` applies it with one multiply per shot (ties included). It is reset to 1 by `StartMatch`, by the next non-LAST-LIGHT standoff, on `MatchOver`, at match-end hand-off, on `Stop()` and when entering review. Void replays re-evaluate from the same HP, so they stay LAST LIGHT. The bot's reaction model is unaffected. Grades and reactions are unchanged.
- **LAST LIGHT presentation.** The dawn plate crossfades in (`StreetScene.SetDawn(1)`, wired with `DuelDirector.SetStreet`). The round sign reads LAST LIGHT in signal yellow (`DuelHud.SetRoundLabel`). In the standoff, the heart monitor takes GET READY's place and runs `suddenDeathFlatLineSeconds` (1.2 s) flat (`EcgMonitor.FlatLine`). Then comes one big QRS spike with a heartbeat thump, a strong haptic and a vignette thump, and the rhythm resumes. The standoff is stretched to at least flat + 0.55 s, before "3". So the flat line never overlaps the hold and can't hide the cue. The hold music ducks a further `suddenDeathMusicDuckDb` (6 dB ⇒ ×0.501 on top of the usual 0.5), and hold heartbeat one-shots are ×`suddenDeathHeartbeatGain` (1.1, capped at AudioSource volume 1, so the loudest frenzied beats can't go above it). The dawn returns to noon when the match-end beat hands off to the match screen (not at the KO, so the killing blow happens at dawn), at the next normal standoff, or at `Stop()`.
- **PvP parity: the server must mirror the rule.** `supabase/functions/_shared/duel/sudden_death.ts` ports `SuddenDeath`. `authority.ts` has the same latched `damageMultiplier` and single multiply. `recorded_match.ts` calls `auth.setDamageMultiplier(suddenDeathMultiplier(cfg, auth.match))` before every attempt, exactly as the client director does. `config.ts` parses the three rule keys (`suddenDeathEnabled`, `suddenDeathHp`, `suddenDeathDamageMultiplier`). The presentation keys stay client-only. Any future change to the trigger (threshold, inclusivity, "both alive") or to the multiplier must land in C#, TypeScript and `Tools/Parity/reference_vectors.py` together. `vectors.json` was regenerated with `reference_vectors.py` (C# `ParityVectorsTests` uses the same driver change). Meta now records the three rule keys. `double_ko_draw` changed (its third round is LAST LIGHT: 80/80 instead of 40/40, same double-KO result). Three cases are new: `last_light_ko`, `last_light_void_then_tie` and `one_low_no_last_light`. Single-exchange "rounds" vectors stay ×1, because the driver, not the authority, decides.
- **Bridge.** `ReviewDirector.SetHp "20 20"` sets hero/bandit HP between exchanges (in the standoff, the standoff restarts and the rule applies at once; on the result card it applies from the next standoff; it's refused mid-exchange). `ReviewDirector.Show lastlight` gives a still of the LAST LIGHT standoff. `Status` reports `lastLight=` and `dmgMult=<this round>/next <pending>`.
# M4 notes: Online client for recorded ghost PvP (SPEC_V2 §4.0–4.6)

- **One seam for slot 1.** `IOpponent` (Core) is all DuelDirector needs from its opponent. `BotClient` implements it with explicit one-line forwards, so the bot's behaviour, RNG stream and timing are unchanged. `GhostOpponent` implements it by pressing through its own `DuelClient` on the same transport, so the authority validates and orders a ghost's ShotReport exactly like the bot's or the player's. `IOpponent.HostActing` is false for a ghost, so there are no feints, tells or banter staged for a real player's recording.
- **Attempt matching.** Attempt k (the k-th `StartCountdown`, void replays included) plays recording attempt k, as `recorded_match.ts` does. The match ends on `RecordedMatchRules`, checked before each attempt and after each resolved round: KO / double KO, 3 resolved rounds, 9 attempts, then the ghost recording running out. HP decides when nobody fell. DuelDirector calls `MatchState.Finish` for the HP verdict. `LocalAuthority` is untouched.
- **Early fouls.** An early foul is replayed at "3" + `inputOffsetNs`, which is measured from the ghost's own `CountdownStartNs` (one frame after the player's, the same as the bot). When the offset is unknown it falls back to 1 s, the server harness default. If our cue arrives first, it is pressed 1 ns before our presented cue, so it can never become a shot.
- **No void on background in PvP.** The server cannot see a void, so `VoidForLifecycle` does nothing when PvP rules are active and the player records a no-shot. To keep the ghost's side right after a long frame, `IOpponent.PreAuthorityTick` delivers any press that is already due before the authority ticks. This is a no-op for the bot.
- **Recording source of truth.** `TapTransport` wraps the loopback transport in every mode. It is a pure pass-through, and in PvP its observer is `RecordingBuilder`. Each entry comes from the player's real ShotReport (kind / reaction / cue / input / source / frameQuantized), plus `countdownStartNs` from the player's DuelClient. An attempt without a report is `noshot` and carries the presented cue. Presentation is never read.
- **Hard for PvP.** `PawGame.StartPvpDuel` copies the Hard rules into the shared config and `ShowTitle` restores the stored difficulty. The pattern is the same as M1's in-place `CopyFrom`. The EASY/HARD toggle is hidden while an online card is up, and the HUD and round card tags read HARD. The solo seed sequence is restored after PvP.
- **Server verdict wins.** The strip under the match result shows the server's own recompute. When it differs from the local result, that is only logged, never shown as a contradiction.
- **Mock = the server's math.** The mock verdict is `RecordedMatchSim`, a C# twin of `playRecordedMatch` on a synthetic clock, so `StartGhostDuel` doubles as a client-vs-server parity check in the Editor (`Status ... agree=yes`). A TS mirror of the frame-driven client was fuzzed over 3000 matches against the server's authority port with zero disagreements while M4 was built. It was not committed, and the EditMode tests cover the same cases in C#.
- **Networking.** UnityWebRequest only. A hidden `NetHost` MonoBehaviour runs the coroutines. Each call gets a timeout, one retry on transient failures (no answer, 408, 429, a bare 5xx) and one re-auth on 401. A 5xx that carries a real error code (503 `no_opponent`) is not treated as offline. Undelivered `match-submit`s go to `persistentDataPath/pn_submit_queue.json` and are flushed on launch and after the next successful call. Definitive answers (409 / 422 / 404 / 400) drop them.
- **Auth.** Anonymous guest on first online use (`POST /auth/v1/signup {}`), with the tokens in PlayerPrefs (`pn_auth_*`) and a refresh 60 s before expiry. If the refresh is refused, the client signs in as a new guest. `SupabaseAuth.LinkIdentity` is the M6 seam for Apple / Google.
- **UI.** No new art. PVP is a second `panel_wood` sign under PLAY, 30 px tall against PLAY's 36 so PLAY stays the primary action. The title reserves 118 px under PLAY now (it was 84). FRIEND (`net_config.json` `friendDuel`) splits the PVP row 92 + 56. The cards reuse the first-launch choice card's look and thumb-zone placement (panel_wood, dim, btn_large). The result strip is panel_paper under the stats panel and above Blackpaw's hat. Text is clipped to the bitmap fonts' glyphs (rival names: upper case, at most 14 characters).

# Haptics review: Core Haptics, Android effects, haptics lab (SPEC_V2 §8.6, Docs/HAPTICS.md)

- **One design table.** Every haptic moment is a preset in `Core/HapticDesign.cs`. A preset is a list of events (time, duration, intensity and sharpness ramps), and `Runtime/HapticMoments.cs` names one method per moment. iOS and Android compile the same data, so the two platforms feel like the same game, and the lab plays exactly what the duel plays. The §8.6 stamp table is unchanged.
- **iOS moved to Core Haptics.** One `CHHapticEngine` (`playsHapticsOnly`, auto-shutdown when idle) is started in `DuelDirector.StartMatch` through `PawHaptics.Prepare()`. It is held up for 12 s after every `Prepare` (the countdown and the hold call it every second). Players are precompiled per preset and per 0.05 scale level, so nothing is allocated per beat. `resetHandler` drops the players, restarts the engine and re-warms. `stoppedHandler` marks the engine down. While the engine is down, the UIKit generators play the preset's transients. `Notify` stays on `UINotificationFeedbackGenerator`, the system's own error / warning language.
- **DRAW haptic at photon time.** The old `Impact(2)` fired at frame start, about one frame early. `PresentDraw` now passes the DRAW sound's own lead (`cuePresentedNs − now`) to `PawHaptics.ScheduleDrawCue`, which takes off the backend's output latency (assumed 0 ms for Core Haptics and 10 ms for Android, to be measured) and starts the player at that time on the engine clock (Android: `sendMessageAtTime` on a haptic thread). It is one native call in place of the old one. Input timestamps, `ShotReport`s and the DRAW presentation timing are untouched.
- **Heartbeat.** It is now a lub-dub (225 ms apart, matched to `sfx_heartbeat`) with low sharpness. It is still silent below frenzy 0.35 and then scales from 0.30 to 0.80 (`HapticPolicy.HeartbeatScale`). A skipped beat adds 0.10, capped at 0.80.
- **New moments.** The swipe gets a leather swish + click (before the recoil at the fire frame). A hit dealt is a dry tock 45 ms after the recoil, and a kill adds a slow-mo rumble. A hit taken is a low body blow instead of a warning notification. Win and lose fire as the match banner lands (rising taps vs a sinking fade). The bandit's shot deliberately has no haptic.
- **Android rewrite.** `PawHapticsBridge.java` uses VibratorManager on API 31+, Composition primitives where supported, amplitude waveforms (`HapticRaster`, unit-tested) or on/off with taps kept as full pulses, predefined effects for plain taps, a high-priority haptic thread, `USAGE_MEDIA` attributes on 33+, and the system Touch feedback setting. Hot calls are raw JNI with reused args. Before, every haptic allocated `AndroidJavaObject`s.
- **Reduced Motion** plays the first pulse of every rhythm (stamps, lub-dub, misfire, tie, win), as before for stamps. Single gestures play whole.
- **Haptics lab.** `ReviewDirector.Show haptics`, or on a device hold the title's top-left corner for 1.5 s. It has 28 buttons, plays each on finger-down, and has PLAY ALL. `ReviewDirector.Haptic <name>` plays one from the bridge, and `Status` reports `haptics=on|off`.
- **Fairness note.** A felt DRAW is a cue, and touch reaction beats sight. This was true before (the cue was early). It is now consistent, and the platform latency difference is documented. Strict PvP parity would need a server rule on the DRAW haptic.
